## Raw telemetry and analysis

The complete UTF-16 terminal capture is in
`full_run_2026-11-12.txt`. The measured headline values are below.

### Phase 0

The measured `perf_counter_ns()` call latency was **88.0587 ns**.

### Phase 1: false sharing

At `p=6`, stride medians were: stride 1 **754.682 ms**, 2 **1383.462 ms**,
4 **1254.488 ms**, 8 **1386.869 ms**, 16 **1271.015 ms**, and 32
**1414.416 ms**. The isolated stride-16 run was not faster on this noisy
Windows process-launch workload, so a cache-line boundary cannot be claimed
from this run alone. At `p=12`, stride 1 was **1094.568 ms** and stride 16
was **1087.476 ms**.

### Phase 2: scaling

Strong-scaling time decreased from **2995.906 ms** at `p=1` to
**536.681 ms** at `p=12`, for observed speedup **5.5823**. The measured
serial fraction was **0.070063**. Weak-scaling time ranged from
**564.216 ms** at `p=1` to **939.685 ms** at `p=12`.

### Phase 3: roofline

The six-worker run measured **2.1975 GB/s** sustained copy bandwidth and
**0.1677 GFLOP/s** compute throughput. The resulting measured ridge point was
**0.076331 FLOP/byte**.

### Phase 4: scheduling

Block static took **24854.597 ms** with cyclic static at **15319.219 ms**.
Dynamic scheduling was fastest at chunk **64**, taking **14343.952 ms** with
lambda **1.022**. Chunk 1024 increased lambda to **1.433** and wall time to
**18520.081 ms**, showing the expected tail-imbalance trade-off.

The current implementation does not yet include the assignment's GEMM
variants/tile sweep or OS cache-topology query; those fields are explicitly
marked unavailable rather than fabricated.
