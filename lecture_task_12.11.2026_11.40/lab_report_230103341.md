## Phase 1 — False sharing and Karp–Flatt

The run used `M = 16,000,000`, two warmups, seven timed samples, and
`SharedMemory(create=True, size=4096)`.

| Stride | Bytes | Median ms | IQR ms | Mops/s |
|---:|---:|---:|---:|---:|
| 1 | 8 | 1403.072 | 103.365 | 11.404 |
| 2 | 16 | 1385.897 | 30.681 | 11.545 |
| 4 | 32 | 1348.652 | 53.895 | 11.864 |
| 8 | 64 | 1334.728 | 57.164 | 11.987 |
| 16 | 128 | 1349.644 | 181.554 | 11.855 |
| 32 | 256 | 1349.901 | 58.564 | 11.853 |

The measured minimum was at 64-byte separation, so this Python process-launch
experiment does not isolate a clean coherence boundary. The expected
64-byte x86-64 line is still the hardware interpretation for stride 8; OS
scheduling and process startup noise are material.

For each `p=1..12`, the raw output includes `T_p`, speedup, efficiency, and
the Karp–Flatt value for stride 1 and stride 16. At `p=12`, stride 1 was
1209.188 ms with `e=0.153162`; stride 16 was 1031.687 ms with `e=0.117088`.

Observed strong speedup at `p=12` was **6.3395x**. The measured serial
fraction was **0.021040**, giving an Amdahl ceiling of approximately **47.53x**.
Weak time rises from 1671.923 ms at one worker to 1900.783 ms at twelve
workers. The six-to-seven worker transition crosses from physical cores into
SMT: strong time improves by 12.26%, while weak time worsens by 8.43%.

## Phase 3 — Roofline and cache-blocked GEMM

The roofline run used six physical workers, two 64 MB copy buffers, and a
60,000,000-FLOP unrolled scalar FMA workload.

| Quantity | Result |
|---|---:|
| Sustained bandwidth | 2.3236 GB/s |
| Sustained compute ceiling | 0.1366 GFLOP/s |
| Ridge point | 0.058769 FLOP/byte |

GEMM used `N=256` and flat double-precision shared buffers. All blocked
variants matched the reordered variant with maximum absolute error below
`1e-9` (the measured errors were `0.000e+00`).

| Variant / tile | Median ms | GFLOP/s |
|---|---:|---:|
| Naive `i-j-k` | 1040.999 | 0.032233 |
| Reordered `i-k-j` | 1221.524 | 0.027469 |
| Blocked BS=8 | 1423.368 | 0.023574 |
| Blocked BS=16 | 1291.769 | 0.025976 |
| Blocked BS=32 | 1192.667 | 0.028134 |
| Blocked BS=64 | **1102.968** | **0.030422** |
| Blocked BS=96 | 1219.044 | 0.027525 |
| Blocked BS=128 | 1269.761 | 0.026426 |

The best tested tile was `BS=64`, with a nominal tile working set of
`3 × 128² × 8 = 393,216` bytes. That exceeds L1 and fits within the 6 MB
per-system L2 capacity reported by the host query only when interpreted as
the aggregate CIM value; cache residency is therefore not guaranteed.

## Phase 4 — Skewed scheduling

The run used `N=8000`, `K(i)=1+floor(i/40)^2`, and dynamic chunks
`{1,8,64,512}`.

| Strategy | Chunk | Wall ms | Lambda |
|---|---:|---:|---:|
| Contiguous block static | — | 22998.501 | not retained |
| Cyclic static | — | 11082.593 | not retained |
| Dynamic queue | 1 | **10257.402** | **1.004** |
| Dynamic queue | 8 | 10361.800 | 1.006 |
| Dynamic queue | 64 | 10720.637 | 1.065 |
| Dynamic queue | 512 | 14085.482 | 1.328 |

Chunk 1 produced the best wall time and near-perfect active-time balance.
Chunk 512 reduced counter claims but left a heavier tail, increasing lambda
to 1.313.
